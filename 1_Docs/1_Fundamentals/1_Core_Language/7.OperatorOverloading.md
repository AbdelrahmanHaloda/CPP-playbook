
## Operator Overloading
It can be done on any operator from the ASCII table and give it your own set of rules!

In order to overload an operator, use the operator keyword in the function signature:

```c++
ReturnType operatorOp(const ClassName& other) {
  /*
  * where Op is the operator to be overloaded
  * It can be +, - , *, /, or any operator
  */
  //...logic to overload the operator
}
```
# Operator overloading

## Why this matters
Operator overloading allows user-defined types to behave naturally with C++ syntax. When used correctly, it improves readability and expressiveness.

When used incorrectly, it creates confusing and misleading code.

---

## Core idea
C++ allows classes to define the behavior of operators such as `+`, `-`, `==`, `[]`, and `()`.

This is done by overloading operators using the `operator` keyword.

---

## Simple example
```cpp
class Point {
public:
    int x, y;

    Point(int xVal, int yVal) : x(xVal), y(yVal) {}

    Point operator+(const Point& other) const {
        return Point{x + other.x, y + other.y};
    }
};

Point p1{1, 2};
Point p2{3, 4};
Point p3 = p1 + p2;
```

---

## Commonly overloaded operators
- arithmetic (`+`, `-`, `*`, `/`)
- comparison (`==`, `!=`, `<`, `>`)
- assignment (`=`)
- subscript (`[]`)
- function call (`()`)
- stream (`<<`, `>>`)

---

## Member vs non-member

### Member operator
```cpp
Point operator+(const Point& other) const;
```

- left operand is the current object

### Non-member operator
```cpp
Point operator+(const Point& a, const Point& b);
```

- useful for symmetry
- allows implicit conversions on both operands

---

## Design rules (very important)

### 1. Preserve intuitive meaning

Good:
- `a + b` adds
- `a == b` compares equality

Bad:
- redefining `+` to mean subtraction

---

### 2. Prefer clarity over cleverness
Operator overloading should make code easier to understand, not harder.

---

### 3. Use const correctness

```cpp
Point operator+(const Point& other) const;
```

---

### 4. Avoid overloading everything
Only overload operators that make sense for the type.

---

## Stream operator example

```cpp
#include <iostream>

class Point {
public:
    int x, y;

    friend std::ostream& operator<<(std::ostream& os, const Point& p) {
        return os << "(" << p.x << ", " << p.y << ")";
    }
};
```

---

## Operator overloading vs function calls

```cpp
a + b        // operator syntax
add(a, b)    // function syntax
```

They are equivalent in behavior, but operator syntax is often more natural.

---

## Common mistakes
- breaking intuitive meaning
- forgetting `const`
- returning incorrect types
- overusing operator overloading
- hiding expensive operations behind simple syntax
