# Value Categories, Types, and References

- Types
- Expressions
- Value Categories (lvalue, prvalue, xvalue)
- References (lvalue reference, rvalue reference)
- `std::move`
- Common traps

---

## 1. Types vs Expressions

## Types

Types describe **what something is**.

```cpp
int a;
double b;
int* p;
```

- Known at **compile-time**
- Describe memory layout and behavior

---

## Expressions
Expressions are **anything that produces a value**.

```cpp
a;
a + 1;
&a;
5;
```

---

## Critical Rule

> Value categories belong to **expressions**, NOT types.

---

## Example

```cpp
int a = 5;
```

| Element | What it is |
|---------|------------|
|  `int`  |    type    |
|   `a`   | expression |
|   `5`   | expression |

---

## 2. Value Categories

- Value Categories aren't really language feature.
- Rather, they're semantic properties of expressions.
- Understanding them provides valuable insights into:
  - built-in and user defined operators.
  - reference types
  - otherwise cryptic compiler error messages
- C++ classifies **expressions** into value categories.
- Every expression in C++ is either an lvalue or an rvalue.
- In general:
  - An lvalue is an expression that refers to an object.
  - An rvalue is simply any expression that isn't an lvalue.
- Caveat:
  - This is true for non-class types.
  - It's not true for class types.

---

## Lvalues and Rvalues have evolved

- In early C, there were two value categories: lvalues and rvalues.
- They associated concepts were fairly simple.
- Early C++ came along, added classes, const and references.
- The concepts got more complicated.
- C++ needed more value categories to specify the associated behaviors.

### lvalues

- In the C programming language:
- lvalue comes from the assignment expression `E1 = E2`
- In which the **left** operand E1 must be an lvalue expression.
- An lvalue is an expression referring to an object.
- An object is a region of storage.
- An lvalue can appear on either side of an assignment operator

### rvalues

- Most literals are rvalues, including:
  - numerical literals, such as 3 and 3.1213141
  - character literals, such as 'a'
  - They don't necessarily occupy data storage.
- However, character string literals, such as "abdo", are lvalues.
- They occupy data storage.
- Because these things have to behave like arrays, you need to be able to step through them with a pointer and inorder to do that, the thing has to live in a well defined location in memory.

## 2.1 lvalue

> Has identity (you can refer to it)

```cpp
int a = 5;
a;
```

Properties:
- Has a name or identity
- Can take address: `&a`
- Can assign to it: `a = 10`

---

## 2.2 prvalue (pure rvalue)

> Temporary value with no identity

```cpp
a + 1;
5;
```

Properties:
- No identity
- Cannot assign to it
- Cannot take address

---

## 2.3 xvalue (expiring value)

> Has identity, but is about to be moved from

```cpp
std::move(a);
```

Properties:
- Has identity
- Can be moved from
- “About to expire”

---

# 3. References (TYPES, NOT CATEGORIES)

References are **types**, not value categories.

## 3.1 lvalue reference

```cpp
int a = 5;
int& ref = a;
```

- Can bind only to **lvalues**

---

## 3.2 rvalue reference

```cpp
int&& ref = 5;
```

- Can bind to **rvalues**

---

## Critical Rule

> References do NOT define value category  
> They only restrict what they can bind to

---

# 4. THE MOST IMPORTANT RULE

> **Every named variable is an lvalue expression**

---

## Examples

```cpp
int a = 5;
int& ref = a;
int&& x = 5;

a;     // lvalue
ref;   // lvalue
x;     // lvalue  ❗ IMPORTANT
```

Even:

```cpp
int&& x = 5;
x;   // lvalue
```

---

# 5. Parentheses DO NOT change value category

```cpp
int a = 5;

a;        // lvalue
(a);      // lvalue
(((a)));  // lvalue
```

---

# 6. Understanding std::move

## What people think:
> It moves objects ❌

## What it actually does:

```cpp
std::move(a);
```

is:

```cpp
static_cast<int&&>(a);
```

---

## Meaning

> “Treat this object as something that can be moved from”

---

## Result

```cpp
std::move(a);   // xvalue
```

---

# 7. Key Comparison Table

| Expression | Type | Value Category |
|----------|------|----------------|
| `a` | `int` | lvalue |
| `a + 1` | `int` | prvalue |
| `std::move(a)` | `int&&` | xvalue |
| `x` (`int&& x`) | `int&&` | lvalue |

---

# 8. Common Pitfalls (IMPORTANT)

## ❌ Mistake 1: Confusing type with value category

```cpp
int&& x = 5;
x;  // lvalue ❗
```

---

## ❌ Mistake 2: “rvalue reference means rvalue”

Wrong.

```cpp
int&& x = 5;
x; // lvalue
```

---

## ❌ Mistake 3: “temporary object = prvalue always”

Better phrasing:

> prvalue = value with no identity

---

## ❌ Mistake 4: Using “memory” as rule

Wrong:

```cpp
a + 1;  // still rvalue
```

---

## ❌ Mistake 5: Thinking std::move moves

Wrong:

```cpp
std::move(a); // only cast
```

---

# 9. Quick Rules (Cheat Sheet)

---

## Rule 1
> Types ≠ value categories

---

## Rule 2
> Value categories apply only to expressions

---

## Rule 3
> Named variables are ALWAYS lvalues

---

## Rule 4
> `std::move(x)` → xvalue

---

## Rule 5
> `a + b` → prvalue

---

## Rule 6
> Parentheses don’t change value category

# 10. Practice Questions (with answers)

---

## Q1

```cpp
int
```

Answer:
- Not an expression → no value category

---

## Q2

```cpp
int a = 10;
(a)
```

Answer:
- lvalue (parentheses don’t change anything)

---

## Q3

```cpp
a + 1
```

Answer:
- prvalue (temporary value, no identity)

---

## Q4

```cpp
std::move(a)
```

Answer:
- xvalue (expiring object)

---

## Q5

```cpp
int&& x = 5;
x
```

Answer:
- lvalue (named variable rule)

---

## Q6

```cpp
int& ref = a;
ref
```

Answer:
- lvalue (alias of `a`)

---

# 11. Final Mental Model

---

### Step 1: Ask

> Is this a type or expression?

### Step 2: If expression → ask

> Does it have identity?

- yes → lvalue or xvalue  
- no → prvalue  

---

### Step 3: If identity + movable → xvalue

```cpp
std::move(a)
```

---

# 12. One-Line Summary

> Types describe variables  
> Expressions produce values  
> Value categories describe expressions  
> References bind to categories  
> `std::move` enables moving by turning lvalues into xvalues
