## Overview

This note explains:

---

## Types vs Expressions

### Types

Types describe **what something is**.

```cpp
int a;
double b;
int* p;
```

- Known at **compile time**
- Describe memory layout and behavior

---

### Expressions

Expressions are **pieces of code that produce a value**.

```cpp
a;
a + 1;
&a;
5;
```

---

### Critical Rule

> Value categories belong to **expressions**, NOT types.

---

### Example

```cpp
int a = 5;
```

| Element | What it is |
| ------- | ---------- |
| `int`   | type       |
|   `a`   | expression |
|   `5`   | expression |

---

## Value Categories

- Value categories are not really a standalone language feature.
- They are semantic properties of expressions.
- Understanding them provides valuable insights into:
  - Built-in and user-defined operators.
  - Reference types.
  - Otherwise cryptic compiler error messages.
- C++ classifies **expressions** into value categories.
- Every expression in C++ is either an lvalue or an rvalue.
- In general:
  - An lvalue is an expression that refers to an object.
  - An rvalue is simply any expression that isn't an lvalue.
- Caveat:
  - This is true for non-class types.
  - It's not true for class types.

---

### Historical Context

- In early C, there were two value categories: lvalues and rvalues.
- Their associated concepts were fairly simple.
- Early C++ added classes, `const`, and references.
- The concepts got more complicated.
- C++ needed more value categories to specify the associated behaviors.

#### lvalues

- In the C programming language, `lvalue` comes from the assignment expression `E1 = E2`.
- In that expression, the **left** operand `E1` must be an lvalue expression.
- An lvalue is an expression referring to an object.
- An object is a region of storage.
- An lvalue can appear on either side of an assignment operator.

#### rvalues

- Most literals are rvalues, including:
  - Numerical literals, such as `3` and `3.1213141`.
  - Character literals, such as `'a'`.
- These do not necessarily occupy data storage.
- However, character string literals, such as `"abdo"`, are lvalues.
- They occupy data storage.
- They need to behave like arrays, so you must be able to step through them with a pointer. That requires a well-defined location in memory.

### lvalue

> Has identity (you can refer to it)

```cpp
int a = 5;
a;
```

Properties:

- Has identity
- Can take address: `&a`
- Can assign to it: `a = 10`

---

### prvalue (pure rvalue)

> A temporary value with no identity

```cpp
a + 1;
5;
```

Properties:

- No identity
- Cannot assign to it
- Cannot take address

---

### xvalue (expiring value)

> Has identity, but is about to be moved from

```cpp
std::move(a);
```

Properties:

- Has identity
- Can be moved from
- "About to expire"

---

## References Are Types, Not Categories

References are **types**, not value categories.

### lvalue reference

```cpp
int a = 5;
int& ref = a;
```

- Can bind only to **lvalues**

---

### rvalue reference

```cpp
int&& ref = 5;
```

- Can bind to **rvalues**

---

### Critical Rule

> References do NOT define value category  
> They only restrict what they can bind to

---

## Named Variables Are Always Lvalues

> **Every named variable is an lvalue expression**

---

### Examples

```cpp
int a = 5;
int& ref = a;
int&& x = 5;

a;     // lvalue
ref;   // lvalue
x;     // lvalue  ❗ IMPORTANT
```

Even:

```cpp
int&& x = 5;
x;   // lvalue
```

---

## Parentheses Do Not Change Value Category

```cpp
int a = 5;

a;        // lvalue
(a);      // lvalue
(((a)));  // lvalue
```

---

## Understanding `std::move`

### What people think

> It moves objects ❌

### What it actually does

```cpp
std::move(a);
```

It is equivalent to:

```cpp
static_cast<int&&>(a);
```

---

### Meaning

> "Treat this object as something that can be moved from."

---

### Result

```cpp
std::move(a);   // xvalue
```

---

## Quick Comparison Table

| Expression | Type | Value Category |
| ---------- | --------- | -------------- |
| `a` | `int` | lvalue |
| `a + 1` | `int` | prvalue |
| `std::move(a)` | `int&&` | xvalue |
| `x` (`int&& x`) | `int&&` | lvalue |

---

## Common Pitfalls

### ❌ Mistake 1: Confusing type with value category

```cpp
int&& x = 5;
x;  // lvalue ❗
```

---

### ❌ Mistake 2: "rvalue reference" means "rvalue"

Wrong.

```cpp
int&& x = 5;
x; // lvalue
```

---

### ❌ Mistake 3: "temporary object = prvalue always"

Better phrasing:

> prvalue = value with no identity

---

### ❌ Mistake 4: Using "memory" as the rule

Wrong:

```cpp
a + 1;  // still rvalue
```

---

### ❌ Mistake 5: Thinking `std::move` moves

Wrong:

```cpp
std::move(a); // only cast
```

---

## Quick Rules

---

### Rule 1

> Types are not value categories.

---

### Rule 2

> Value categories apply only to expressions.

---

### Rule 3

> Named variables are always lvalues.

---

### Rule 4

> `std::move(x)` produces an xvalue.

---

### Rule 5

> `a + b` is a prvalue.

---

### Rule 6

> Parentheses do not change value category.

## Practice Questions

---

### Q1

```cpp
int
```

Answer:

- Not an expression, so it has no value category.

---

### Q2

```cpp
int a = 10;
(a)
```

Answer:

- lvalue. Parentheses do not change anything.

---

### Q3

```cpp
a + 1
```

Answer:

- prvalue. It is a temporary value with no identity.

---

### Q4

```cpp
std::move(a)
```

Answer:

- xvalue. It refers to an expiring object.

---

### Q5

```cpp
int&& x = 5;
x
```

Answer:

- lvalue. This follows the named-variable rule.

---

### Q6

```cpp
int& ref = a;
ref
```

Answer:

- lvalue. `ref` is an alias of `a`.

---

## Final Mental Model

---

### Step 1: Ask

> Is this a type or expression?

### Step 2: If expression → ask

> Does it have identity?

- Yes -> lvalue or xvalue
- No -> prvalue

---

### Step 3: If identity + movable → xvalue

```cpp
std::move(a)
```

---

## One-Line Summary

> Types describe what something is.
> Expressions produce values.
> Value categories describe expressions.
> References bind to certain kinds of expressions.
> `std::move` makes an lvalue behave like an xvalue.
